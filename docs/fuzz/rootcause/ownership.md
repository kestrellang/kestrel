# Ownership bugs: root-cause analysis (no fixes)

Base: /home/user/kestrel @ 3fea2041eef543c99ac62c296e1fbba8b30af401, prebuilt ./target/release/kestrel. I re-ran every repro: each one reproduces as REPORT.md describes.

## Group A: no ownership check on borrowed params in move_tracking (C13, C14, H16)
`move_tracking.rs` only rejects moves out of *pattern bindings* of a borrowed scrutinee (`borrow_bound`, `compute_borrow_bound` :1098). It has no rule for moving or deinit-ing a whole non-`consuming` parameter, even though `local_is_owned_place` (:1133) already gives the answer. Plain borrowed params are caught later only by the MIR copy backstop (mir-lower body/mod.rs:2103, `emit_move_out_of_borrow_backstop`), because they are SSA @guaranteed values.

- **C13** (move out of `mutating` param). A `mutating` param binds as a Var slot (`PtrTo %v0`). The var-read consuming path in `lower_expr` (kestrel-mir-lower/src/body/expr.rs:335-400, the `is_non_copyable` → `emit_take` arm) takes from it like an owned `let`/`var`, and never checks that the slot is reinitialised before return. The verifier treats the param address as untracked (`addr_require_init` passes), and nothing checks the inout slot at exit. Result: the caller drops it again. `record_move` (move_tracking.rs:1391) has no param check. Confidence: high. Fix shape: in `record_move`, emit E503 when `!local_is_owned_place(root)` for a param root (or, for `mutating`, require reinit on every exit), and make the expr.rs take path refuse @guaranteed/inout slots.
- **C14** (`deinit r` on a borrowed param). The `HirStmt::Deinit` arm (move_tracking.rs:379-423) checks freeze and use-after-move but never ownership. MIR lowering (kestrel-mir-lower/src/body/stmt.rs:85-106) then emits `destroy_value %v0` on a @guaranteed param. `try_consume_exempting` (kestrel-mir/src/verify.rs:1229-1232) returns `true` ("not tracked") for non-Owned values, so the verifier accepts destroying a borrow. Confidence: high. Fix shape: reject `deinit` of a non-owned local in the Deinit arm via `local_is_owned_place`, and make DestroyValue of a @guaranteed operand a verifier error.
- **H16** (`deinit r;` as the only statement panics). `deinit_site` (move_tracking.rs:2263-2279) looks for a `HirExpr::Local` read of the local, then falls back to "first expr in arena" and `.expect`s. A body `{ deinit r; }` has no expressions at all, because HirStmt::Deinit carries the local, not an expr. Confidence: high. Fix shape: key `MoveInfo.site` on a span (or give HirStmt::Deinit its own HirExprId) instead of synthesizing an expr id.

## Group B: E498 attribution only knows `ret_borrow` call results (H4, all 3 repros)
For `let r = &a`, `lower_borrow_init` (mir-lower body/mod.rs:3746) lowers to a plain `begin_borrow_addr`. It is recorded in `ref_binding_vals` (lowering only). The verifier's `refs` map is populated only from @guaranteed *call results* (verify.rs:1976-1982). So `check_take_while_borrowed` (verify.rs:1294-1316) / `live_ref_rooted_at` (:1355) find no user ref and emit the uncoded ICE "cannot take from …: active borrow(s)". The frontend has no move-while-borrowed rule either: move_tracking's freeze set (`state.frozen`, :780-790) is fed only by view-closure captures, never by `&x` bindings.
- `ossa_move_while_ref_live`: the live named ref is not attributed.
- `ossa_consume_and_mutate_same_arg` `f(x, x)`: the mut-borrow arg temp is live while the consuming arg takes the same slot. `apply_call_moves` (move_tracking.rs:991) has no exclusivity check between a consuming arg and a mutating/borrow arg on the same root.
- `ossa_match_consumes_while_dead_ref`: the dead binding `r` (zero uses) keeps its borrow until scope end, so value-mode `match e` takes `e` under it.

Confidence: high for the first two, medium for the dead-ref case (the borrow end placement is inferred from the dump). Fix shape: track `&x` binding borrows as freeze/borrow facts in move_tracking (E498 at HIR level, ending at last use), and register ref-binding borrows in the verifier `refs` map so any leftover is coded.

## Group C: var-init state lost at loop exit (H5, both repros)
`lower_loop` (kestrel-mir-lower/src/body/control.rs:245-345) restores the *pre-loop* scope snapshot at the exit block (`restore_scope(&saved_snapshot)`). It joins `field_inits` but not `var_inits`, and `lower_break` (:350) records no per-break var-init state. `while let .Some(r) = o` desugars to loop+match+break, and the match takes `o` (`take %v13`) at the header. On the break/exit edge `o` is DefUninit, but the exit restores it as Init. Scope exit then emits an unconditional `destroy_addr` on the vacated slot, and OSSA reports "address … already uninit". A body without reassignment is rejected earlier by move-checking, so only reassign/break shapes reach this. Confidence: high. Fix shape: collect var_inits at each break site plus the header-fail edge and `fold_var_inits` them at the exit, as `lower_if` does.

## Group D: field move-out paths (C23, M6)
- **C23** (field move skips owner deinit). `try_move_field_out_of_owned` (mir-lower body/expr.rs:113-197) destructures any owned struct with `DestructureStruct` and never checks whether the struct has a user `deinit`. Destructuring bypasses the drop shim, so `P.deinit` never runs. copy-semantics.md:122 says consuming field extraction is legal but is silent on deinit-bearing types. The spec needs to decide: either forbid it (like Rust E0509) or run deinit first. Confidence: high (mechanism), spec-dependent (intended behavior). Fix shape: reject a field move-out of a type with a user deinit in move_tracking (new diagnostic), or bail out in `try_move_field_out_of_owned` when `structs[entity].deinit.is_some()`.
- **M6** (`let x = p.a` / tuple `p.0` rejected). The only field move-out path is `try_move_field_out_of_owned`, called solely from `lower_expr_for_return` (expr.rs:90). Any other consuming position (`let x = p.a`) goes through the generic borrow+`copy_value` path, which hits the E503 backstop (mod.rs:2103). The function also only matches `HirExpr::Field` on structs: `TupleIndex` is excluded ("separate projection arm" that doesn't exist), so `p.0` hits the backstop, and with a synthesized span. Confidence: high. Fix shape: route every consuming use of a non-Copyable projection of an owned local through the move-out path (let/arg/return), and extend it to TupleIndex/tuples.

## Individual bugs
- **C10** (assigning a field in `deinit` drops twice and leaks the new value). Drop shim `__drop$H` (kestrel-mir/src/passes/drop_shim.rs:~218) does `begin_mut_borrow %v0` (an SSA @owned value), calls deinit, then `destructure_struct %v0`. In Cranelift (kestrel-codegen-cranelift/src/inst.rs:121-133), BeginMutBorrow on a *Scalar-repr* operand spills to a fresh stack slot, and EndMutBorrow (:137) never reloads. Writes made in deinit are lost, and the destructure drops the stale old field again. Only scalar-sized types fail: I verified that adding a second field (Aggregate repr) prints correctly "drop 1, drop 2". Confidence: high. Fix shape: the shim should store self into an `uninit` slot, use `begin_mut_borrow_addr`, then `take` + destructure (or codegen reloads the spill at EndMutBorrow).
- **C16** (array literal of non-Copyable elements; `for in` hits SIGILL). `ArraySliceIterator.next` (lang/std/memory/pointer.ks:511-513) calls `self.ptr.read()`, which is `where T: Copyable` (pointer.ks:200), from an unconstrained `T`. The frontend's "Copyable-default substitution hole" (#127) lets `Array[R]` for non-Copyable `R` through. Mono then poisons the instantiation with a Panic body (kestrel-mir/src/mono/mod.rs:128-160, `violated_copyable_bound`), and that is the trap. Confidence: high. Fix shape: enforce the Copyable where-bound in generic bodies / at the `Array[R]` instantiation (reject at compile time), and have the std iterator not bit-copy (borrow or require `T: Copyable` on the conformance).
- **C17** (ref-carrying struct escapes via an outer `var`). Ref-carrier escape checking exists only at returns and globals: MIR `check_escapes` (kestrel-mir/src/verify.rs:2384) checks return values' taint. move_tracking's `check_outlives` (:1520) / `collect_carried` (:1697) only see places frozen by view closures, not `&x` refs wrapped in aggregates. So `c = .Some(Cur(item: &x))` with `c` declared at a shallower depth than `x` is never checked. This contradicts references.md:134/181. Confidence: high. Fix shape: treat a `Borrow{&x}` operand as carrying place `x` at x's scope depth in `collect_carried`, so the existing Let/Assign `check_outlives` fires.
- **C24** (discarded temporary dropped at scope end). The `HirStmt::Expr` arm (kestrel-mir-lower/src/body/stmt.rs:82-84) calls `self.lower_expr(*expr)` and discards the result. The owned value stays scope-tracked and is destroyed at block exit, which violates drop-semantics.md §6. Confidence: high. Fix shape: after lowering an expression statement, destroy its owned result immediately if it is still tracked (`emit_destroy_value` + untrack).
- **M5** (`deinit x;` only parses at function-body top level). Parser gate at kestrel-parser/src/grammar/blocks.rs:134: `Some(K::Deinit) if flavor == BlockFlavor::Top`. Nested blocks fall to expr parsing and give E803. The rest of the pipeline already handles conditional state: move_tracking merges branches, and stmt.rs lowering uses var drop flags. A let-SSA local deinit'd in a branch would need a flag (`emit_destroy_value` in an arm). Confidence: high (location); unclear if the restriction is deliberate (it is not documented). Fix shape: allow `deinit_stmt` in Inline blocks, and make sure SSA-let deinit in a branch uses drop-flag/merge reconciliation.
- **M7** (`match r` on a `&E` binding rejected). `lower_match_scrutinee` (kestrel-mir-lower/src/body/pattern.rs:67-90) is value mode unless an arm has a `&` binder. A named ref binding scrutinee is `lower_expr`'d and copied out ("A named binding scrutinee copies too"). For a non-Copyable pointee, that copy hits the E503 backstop with the whole-match span. Confidence: high. Fix shape: when the scrutinee is ref-typed and the pointee is non-Copyable, use place mode (`lower_match_scrutinee_place`), with arm bindings treated as borrow-bound (add ref-binding scrutinees to `compute_borrow_bound`).
- **A3** (E494 on an if/else of two locals: phantom error count, unnamed local). Two causes:
  1. In a `-> &Int64` body, `if c { x } else { y }` lowers each arm as a *value copy* (`begin_borrow_addr` → `copy_value`), merges into the owned temp `%v33`, then `begin_borrow %v33` + `destroy_value %v33`. The root is that unnamed temp, so `value_names` (verify.rs:~2553) has no name ("borrows local, which…"). A second, *uncoded* verify error (destroying %v33 while it is borrowed) is also produced. The cause is that the ref-return path doesn't lower if/else arms as places.
  2. kestrel-compiler/src/lib.rs:247-262 filters uncoded errors out of display when any coded error exists, but computes the count and the "OSSA verification failed" wording from the unfiltered list.

  Confidence: high. Fix shape: lower ref-returning if/match tails arm-by-arm as borrows (place mode), and compute the summary over the filtered set.
